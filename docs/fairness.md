# Buzz fairness: measured

Generated by `go run ./cmd/fairsim -games 4000 -tossups 20 -seed 1` (`make fairness`): 80000 simulated tossups, 4–8 players each. The simulator drives the real clock estimator (`internal/clock`) and adjudication code (`internal/fair`); only the network, voice chat, and players are simulated.

- **Press-fair**: the player who physically pressed first wins. This is what network correction can fix.
- **Heard-fair**: the player who reacted fastest after *hearing* the clue wins. This also needs each player's voice-chat delay, which QBuzzer can't see while audio goes through Discord or Zoom.
- **Close race**: the two earliest presses were under 25 ms apart.
- **Clamped**: share of honest buzzes whose claimed press time fell outside the allowed correction.
- **Lock delay**: from the first buzz arriving to the winner being locked in (window + 5 ms grace).

## Assumptions

| Parameter | Value |
|---|---|
| Network: LAN | uplink 0.3 + exp(0.2) ms, downlink 0.3 + exp(0.2) ms, 0% spikes up to 0 ms |
| Network: home Wi-Fi | uplink 8.0 + exp(6.0) ms, downlink 8.0 + exp(6.0) ms, 5% spikes up to 80 ms |
| Network: asymmetric uplink | uplink 40.0 + exp(4.0) ms, downlink 8.0 + exp(2.0) ms, 0% spikes up to 0 ms |
| Network: mobile | uplink 30.0 + exp(25.0) ms, downlink 25.0 + exp(20.0) ms, 15% spikes up to 300 ms |
| Voice-chat delay | uniform 80–250 ms per player per game, ±10 ms per tossup |
| Reaction time after hearing the clue | lognormal, median 300 ms, σ = 0.25 |
| Players who know the answer at the deciding clue | each with p = 0.6, at least 2 |
| Clock estimate | after 30 s of real ping exchanges (burst, then every 2 s) |

These are modeling assumptions, not measurements of real voice chat or networks; replace them with pilot data.
